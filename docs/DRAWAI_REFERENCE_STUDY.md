## 与当前项目的差距

1. `ai/scidirector_ai/scene.py`、`scene_revision.py` 和 `scene_runtime.js` 已有对象、锚定线和结构化局部修订；不能把这些写成待从零开发的功能。
2. 研究时网页默认 fy 只返回 palette 与完整代码。第一阶段已新增对象文档和独立的版本校验协议，精确数据修改保留其他对象；普通自然语言模型修复仍不保证这一点。
3. 第一阶段已为登记对象提供边界、运动、端口和诊断；不等于历史任意 Canvas 图形都能直接编辑或精确检测碰撞。
4. `fy_generation.py::shot_timing` 明确采用按镜头时长估算的词锚。后期保留完整旁白或调整镜头总长，不等于动作已对齐实际关键词。
5. 前端 ShotDetail 提供视频预览、意见和文案编辑，尚未提供画面对象选择、拖动、端口修改和对象级差异预览。
6. 当前已有审核账本、前后证据和人工放行机制，后续应复用这些事实记录，避免再建立一套互不一致的质量状态。

## 差异化定位

SciDirector 适合成为“面向讲解视频的可编辑动画制作台”：以旁白和镜头意图组织创作，同时保留对象、关系、时间轴和修订记录。

### 对象与绘制分离

- 在现有场景能力上设计 fy 可用的对象描述层，让需要编辑或碰撞检查的主体拥有稳定 ID、边界、端口、层级和运动轨道。
- 允许对象内部使用自由 Canvas 绘制或已登记素材，保留画风表现力；不要为了可编辑性把所有主体重新限制成矩形卡片。
- 画布选择、诊断、修订和审片引用同一个对象 ID。历史自由代码没有对象描述时，明确标为不支持精确编辑，不能承诺任意旧视频都能直接拖动修改。

### 几何正确与关系正确分别验证

- 关系边保存 source/target/port，端点跟随对象；路由负责几何避障，内容审查负责判断方向和含义。
- 自动线、手工路径和无法布线分别保存状态；拖动对象、连线更新和撤销属于同一个修订。
- 视频增加运动区间的碰撞验证、稳定通道与倒序 seek 检查。不能在每帧无约束地换一条最短线，否则会产生跳线。
- 复杂形状的包围盒碰撞可能误报，需支持明确的碰撞形状与有意叠放关系。装饰层与有效信息对象也需要区分。

### 先定调，再扩展

- 用开场、核心机制、总结等少量代表镜头验证构图、材质、主物件、镜头运动和阅读节奏，再展开完整视频。
- 保存定调镜头采用的视觉规则和可复用部件，不只是增加一份风格提示词。
- 美感验收与几何验收分开：无重叠不是设计优秀，画风编号一致也不是视觉一致。
- 实现适配以具体视觉需求为依据。DrawAI 本身使用 Remotion；仅更换 Remotion、fy 或其他渲染入口不能替代设计和编辑流程。

### 旁白先行与可试听修订

- 为主流水线增加真实旁白时间轴，能拿到逐字时间戳时使用真实词锚；只有时长时明确精度，不能伪称逐字对齐。
- 台词或发音改变后，标记依赖该音轨的动作、字幕和讲解员需要更新；沿用当前完整音轨保护与原产物保留机制。
- 增加段落级试听、术语读法和服务商确实支持的语速/表达控制。先通过同文试听比较判断自然度，再选模型或参数。
- 音量归一、节拍对齐和背景音乐避让可以改善听感，但不能代替音色、韵律及合成文本本身的改进。

## 建议实施顺序

| 阶段 | 交付范围 | 验收依据 |
| --- | --- | --- |
| 1. 单镜对象与修订试点 | 对象描述、关系边、版本校验、局部修改及差异记录；用一个 fy 镜头验证，暂不改全片状态机 | 修改一个对象后，其他对象及旁白不变；冲突版本拒绝写入；移动主体后端点跟随；无路状态可见；重复/倒序 seek 一致。 |
| 2. 前端镜头工作台 | 预览时间轴、对象选择、位置/层级/端口编辑、撤销与诊断定位 | 前端操作与后端修订指向同一对象及产物版本；修改可预览、可回退，仍走已有发布和审核流程。 |
| 3. 定调与视觉部件 | 少量代表镜头、视觉规则快照、可组合主体和转场 | 用实际播放验证设计与节奏；避免只有字幕动画和卡片排列。 |
| 4. 真实旁白排期 | 段落试听、缓存、时间戳接入、依赖失效与重排 | 用已生成音频核对动作/字幕；同文试听确定声音是否改善；改一句只更新必要内容。 |
| 5. 全片证据汇总 | 复用审核账本，关联布局、动态、音频和人工决定 | 区分机器通过、人工接受、未检查与失败，不用单个总分覆盖具体缺陷。 |

首期选择“对象与局部修订试点”，因为前端精确编辑、可控布线和有定位的修复都依赖同一份对象数据。它是小范围能力验证，不承诺一期就能消除所有历史 Canvas 镜头的问题。
