# 导演规划的输出预算

`finish_reason=length` 表示服务商因输出 token 上限结束响应。即使已返回几千个汉字，也可能尚未完成整份分镜 JSON；字符数不等于 token 数。原导演默认使用通用的 4096 token，两次解析调用使用同一上限，长分镜容易连续被截断。

导演现在使用独立设置：

```dotenv
SCID_DIRECTOR_PLAN_MAX_TOKENS=8192
```

- 首次请求使用 `min(4096, 配置上限)`，较短规划无需额外放大预算；默认在明确截断后的第二次请求提高到 8192，覆盖较长的旁白、视觉意图和节拍。
- 只有服务商明确返回 `finish_reason=length` 时，才在原有第二次解析调用内把预算提高到配置上限，并要求从头输出完整 JSON。普通 JSON 或字段校验错误仍以首轮预算重试。
- 最多两次解析调用；截断不会触发额外的传输重试。两次均失败时保留最后原始响应和具体错误，不把完整的内层镜头对象当成整份规划，也不拿缺失后半段的分镜继续生产。
- 服务商的真实输出上限与上下文容量仍适用；此配置不会扩大模型自身能力。支持较低输出上限的模型应相应调低配置；长规划仍可能失败，不能承诺任何长度都能一次完成。

导演提示词要求完整保留必要旁白、事实与顺序，用简短的画面动作、2~5 个节拍短语描述每镜，不逐镜复制画风原文和全局说明。`index` 可省略，由数组顺序生成。配色、代码、坐标、关键帧由后续生成阶段负责，不能混入导演分镜。

该设置已经写入 `.env.example` 并透传到 Compose。宿主运行修改环境后需重启 Python AI 服务；Compose 运行需更新/重建 AI 容器的环境。通用 LLM、场景编码与审核的预算保持各自原值，不需要为这项修复统一放大。

截断错误是独立的 `LLMTruncatedError`（继承 `LLMParseError`），原 JSON 解析与业务失败出口保留。自动化测试使用模型响应夹具验证实际请求参数、计费累计、完整性和有界重试，没有调用真实模型。
