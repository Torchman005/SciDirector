# 审核指南（人怎么审查分镜与成片）

> 面向**审核员**，不是面向开发者。所有判据都取自代码里的真实阈值与真实行为，
> 不是"建议这么做"——每一条都能在源码里找到出处。
> 审核台：`http://127.0.0.1:5173/?job=<任务号>`（任务号可分享、刷新不丢）。

---

## 一、先分清：有两道审查，职责不同

| | 自动审查（VLM Critic） | 人工审查（审核台 / 你） |
| --- | --- | --- |
| 何时 | 每个镜头每次渲染完成后**自动**跑 | 自动重试额度用尽（`AWAITING_HUMAN`），或你主动去看 |
| 看什么 | 抽帧图片 + 画外音 + 画面说明 | 成片、分镜文案、**以及自动审查的全部理由** |
| 产出 | 分数 + 问题 + 可执行建议 | 放行 / 打回 / 改文案 |
| 成本 | 一次 VLM 调用 + 一次渲染（如果判负要重做） | 你的时间 |

**关键**：人工审查不是"重看一遍画面"，而是**在自动审查已经给出的证据上做决策**。
审核台里每次尝试的分数、四维分解、问题与建议都列在「审查依据」里 —— 先读它，再决定。

---

## 二、自动审查到底判什么（决定你不必重复看什么）

四个维度打分（0~1），加权求总分：

| 维度 | 权重 | 看什么 | 常见失分点 |
| --- | --- | --- | --- |
| 逻辑一致性 | **35%** | 画面是否忠实表达画外音与画面意图 | 图文不符；该出现的元素没出现 |
| 文字可读性 | **30%** | 字号、对比度、是否被裁切、标签是否重叠 | 字号过小；深底深字；文字出画 |
| 节奏 | 20% | 抽帧之间的**变化幅度**是否合理 | 首末帧几乎一样；画面静止 |
| 美观度 | 15% | 构图、留白、配色 | 元素挤在角落；信息过载 |

**通过需要四条同时满足**（`critic.py::_decide`）：

1. 加权总分 ≥ **0.70**（`SCID_CRITIC_SCORE_THRESHOLD`，可配置）
2. 逻辑一致性 ≥ **0.70**（硬性下限）
3. 文字可读性 ≥ **0.60**（硬性下限）
4. 无有证据的致命问题，且无未关闭的 `blocking` / `major` 修复任务；模型自报不通过不能凭主观建议单独否决

> 第 2、3 条是**硬性下限**，与总分无关。一个镜头完全可能总分 0.80 却因为可读性 0.55 被判负。
> 审核台会把低于下限的维度**标红并写"低于下限"**，那就是它判负的直接原因。

**字号容差**：低于设计下限的 **90%** 才判"不可读"（例如下限 32px，则 ≥ 28.8px 算"偏小但可读"）。
低于 90% 时 VLM 必须给出"把字号从多少提到多少"的具体建议。

评分以可交付为目标：轻微布局、配色、局部动效不足和正常阅读停留仅记 `advisory`，
不单独触发重做。首帧短暂淡入不算持续空白；不能仅凭缩略图猜测字号而判负。

**自动审查的盲区（要心里有数）**：美观度这类主观项**存在批次间波动** ——
实测同一类镜头在不同批次分别拿到 0.97 与 0.64（理由都是"颜色/对比度"）。
所以"这次没通过"不等于"这次真的更差"。这是模型判定的固有方差，不是系统故障。

## 三、三个动作的真实后果

这是最容易被误解的部分。**逐一对应到源码行为**：

| 动作 | 状态迁移 | 消耗尝试额度？ | 触发什么 |
| --- | --- | --- | --- |
| **放行并继续** | 任意 → `APPROVED` | ❌ **不消耗** | 若**所有**镜头都已通过 → 任务转 `COMPOSING` 并**立即入队合成**（无需再等） |
| **打回重做** | 任意（**含已通过**）→ `RETRYING` | ✅ **+1** | 你的意见作为一条人工反馈回灌给编码智能体 → 重写代码 → 重渲；任务回到 `RENDERING` |
| **编辑文案**（仅保存） | 不变 | ❌ | 只改画外音 / 画面说明 / 背景样式，**不动已渲染的视频** |
| **编辑文案 + 立即重做** | 任意 → `RETRYING` | ✅ **+1** | 同上，但用你改过的**新文案**去重渲 |

三条必须知道的事：

1. **打回是要花额度的。** 额度是 `SCID_PIPELINE_SHOT_MAX_ATTEMPTS`（缺省 3），
   人工打回也 `Attempt++` —— 这是刻意的（避免无限返工）。所以"先打回看看"是有代价的。
2. **已通过的镜头也能打回。** 后来发现成片里某个镜头不对，可以直接打回它，
   任务会从 `COMPLETED` 回到 `RENDERING` 并重新合成。
3. **放行一个没有产物的镜头，任务会变成「部分完成」而不是「已完成」。**
   这是如实标记：那一段画面**根本不存在**，不该显示成一切正常。
   （典型来源：渲染引擎缺失导致熔断的镜头。）

## 四、怎么判断：一张决策表

展开分镜后，先读「审查依据」，再按下表决定：

| 你看到的情况 | 建议动作 | 理由 |
| --- | --- | --- |
| 已经通过，或分数接近 0.70 且问题不实质（"配色可以更好"） | **放行** | 继续重做的期望收益低于它的成本 |
| **最近两次审查意见完全相同**（审核台会主动提示） | 核对当前视频和修复清单，再决定定点修改或人工确认 | 可能修改未生效，也可能审核不稳定；重复意见不是放行证据 |
| 问题具体、可执行，且**改代码能解决**（元素缺失、位置错、文字写错） | **打回**，并在意见里写清"改哪里" | 这是打回**唯一**该用的场合 |
| 问题出在**要求本身**（画外音与画面意图自相矛盾、描述的画面临时画不出来） | **改文案**（可勾选"立即重做"） | 让模型重写代码去满足一个不合理的要求，是白烧渲染 |
| `ERROR` / 渲染失败，且原因是环境类（缺引擎、超时、LaTeX 报错） | 先修复依赖或定位超时，再重做 | 未改变环境的重复执行不能修好缺失依赖 |
| 程序化镜头存在问题 | 调整参数/文案或修复渲染器；确认画面无实质问题后才放行 | 确定性意味着可复现，不意味着内容正确 |
| 分数在 0.6~0.7 之间波动 | 核对证据与逻辑、可读性底线 | 评分方差不能单独证明画面合格 |

### 打回意见怎么写才有效

编码智能体拿到的**只有你写的这段话**（加上它自己的历史尝试）。所以：

**有效的写法** —— 指向**元素**与**位置**，说明**改成什么**：

> 三角形三条边都要标出长度（a=3、b=4、c=5），标注放在边的外侧，字号不小于 36px。

> 第二层右侧补一个标注 ReLU 的方块，并用箭头连入第三层。

**无效的写法**（系统仍会接受，但它转不成任何可执行的改动）：

> 不好看。 ／ 再精致一点。 ／ 感觉不对。

**一条经验**：如果你发现自己**写不出**具体要改什么，那通常说明问题在**画面说明**而不是在代码 ——
这时该用「编辑文案」，把要求写清楚再重做。

## 五、看完成片之后

成片区有三样东西：

1. **内嵌播放器** —— 支持拖动进度条（`artifact` 接口带 Range 支持），不必去文件夹里找文件。
2. **实际生效的效果** 三个标签：`背景音乐 ✓` / `后期处理 ✓（调色名）` / `字幕已烧录`。
   这是从**合成事件里读出来的实况**，不是你的请求 —— 用来回答"为什么没有背景音乐"。
   请求了却没生效，说明那一步降级了（日志与事件时间线里会写明原因）。
3. **文件路径**（可复制），交给外部流程时用。

**成片级审查的重点**：

- **音画同步**：旁白与字幕是否对得上（句级时间戳命中时字幕会落在句子真实起止处）。
- **段落衔接**：转场是否连贯、音轨在转场处是否被 `acrossfade` 平滑处理。
- **整体一致性**：不同引擎（Manim / HTML / 代码动画）出的画面质感是否割裂 ——
  色彩范围与色彩空间已在归一化时统一，但**配色**取决于 `风格预设`。
- **背景音乐是否铺满**：结尾不该突然没声音（配乐会按成片长度循环/裁剪）。

## 六、审核台里能做什么、不能做什么（诚实边界）

**能**：

- 分镜表一眼扫过：标签 / 引擎 / 时长 / 状态 / 尝试次数 / 画外音（截断显示）
- 展开任意分镜看：画外音、画面说明、背景样式、产物路径、**审查依据（分数+四维+问题+建议）**
- 三个动作（放行 / 打回 / 编辑文案），待人工的镜头**默认展开**且行内有「快速放行」
- 事件时间线：出问题时看"怎么变成这样的"，它是最可信的排查来源
- 成片内嵌播放 + 实际生效的效果
- 单镜头当前版本视频播放、原始审核抽帧预览；媒体标注渲染版本
- 最近两次评分变化、完整定向修复清单、验收条件和已验证关闭状态
- `?job=<任务号>` 深链，可分享

**不能（当前）**：

- 不提供任意历史版本视频切换，当前媒体不能代替旧反馈对应的旧画面；反馈文字与任务账本保留历史。
- 单镜头预览尚未应用成片后期/Live2D；最终合成仍需单独验收字幕、配音和角色。

## 七、一分钟速查

```
自动审查通过线 = 总分 ≥ 0.70 且 逻辑 ≥ 0.70 且 可读 ≥ 0.60，且无未解决的阻塞问题
打回 = 花一次尝试额度（缺省共 3 次），意见会回灌给编码智能体
放行 = 不花额度；全部通过时立刻开始合成成片
改文案 = 不动视频；勾"立即重做"才重渲（同样花额度）
同一意见重复出现 → 核对实际画面、目标和验收条件；不能据此直接放行
渲染引擎缺失 → 先补齐环境再重做
放行无产物的镜头 → 任务如实变成「部分完成」
```
